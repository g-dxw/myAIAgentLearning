# Phase 1 功能边界决策记录

基于 2026-05-18 全部 30 条澄清问题回复，确认以下关键决策：

## 纳入 Phase 1
- 认证系统（admin 预置 / fd7105203322，worker 默认密码=身份证后 6 位）
- 护工管理（CRUD + 启用/停用，停用时自动取消待执行排班；无离职流程）
- 病人管理（管理员新增→自审核，含全部扩展字段；**不含批量导入**；特殊情况 4 枚举值）
- 排班管理（24h 手动排班，1h 粒度，严格 1:1，无自动排班，无加钟；**双入口：按病人/按护工**；代班=手动两步操作）
- AI Agent 对话（护工补充已分配病人的信息；**每个病人一个长期 Session 长期记忆模式**；AI 提取可见可编辑；二次确认）
- 打卡（排班详情页进入→开始服务；当日补卡**自由填写时段**；忘记=旷工；无 AI 评分）
- 护理记录查看
- **出勤统计列表**（单独页面，支持按护工/日期筛选；管理员可手动纠正旷工状态）
- **病人档案版本追踪**（记录最后更新人+更新方式）

## 排除（Phase 2+）
- 投诉管理
- 预警系统（含 AI 健康分析、推送、风险等级）
- 加钟/临时调整
- 自动排班算法
- 护工离职流程
- AI 完整性评分（仅跟踪提交/未提交）
- 批量导入病人
- 多机构

## 关键变更点（来自 Round 1：Q1-Q20）
- Q12 彻底改变了 AI Agent 的流程：从"护工新增病人"变为"护工补充已分配病人信息"
- 病人字段大幅扩展（6 个新字段含 4 个 text 长字段）
- Session 状态枚举需要调整（去除 PENDING_REVIEW/APPROVED）

## 关键变更点（来自 Round 2：Q21-Q30）

### Session 与病人信息
- **Q21**：每个病人一个长期 Session（长期记忆模式），护理记录是对话轮次。仅管理员直接修改档案。护工通过每日记录间接贡献。
- **Q26**：病人档案需版本追踪（最后更新人、更新方式、更新时间）

### 排班
- **Q22**：双入口——病人优先（选病人→指派护工）和护工优先（选护工→分配病人）
- **Q22**：代班需管理员手动两步操作（取消原排班→创建新排班），无一键代班

### 打卡与补卡
- **Q23**：补卡时记录实际提交时间，护工自由填写服务时间段（不自动关联排班）
- **Q27**：打卡入口在排班详情页内，"开始服务"按钮不在卡片上直接放置
- **Q30**：服务结束提醒轮询频率为 1 分钟

### 缺勤管理
- **Q25**：需要单独的出勤统计列表，管理员可手动纠正旷工状态
- **Q25**：数据模型预留绩效/考核字段（score, performance_level 等）

### 移动端
- **Q28**：移动 Web 浏览器，不提供 PWA

### 密码重置
- **Q29**：管理员手动线下通知护工，系统不做自动发送

### 已排除（确认）
- **Q24**：批量导入不在 Phase 1 范围内
