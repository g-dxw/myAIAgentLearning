# Day 02 — 文档加载 + 文本分割

## 今日目标
掌握加载多种文档格式（PDF/MD/TXT/HTML）的方法，理解分割策略对检索质量的影响。

---

- [ ] 今日学了什么
  - [ ] 文档加载器：
    - [ ] PDF：PyMuPDF（fitz）— 逐页提取文本
    - [ ] Markdown / TXT：直接 `open().read()`
    - [ ] HTML：`BeautifulSoup` 去标签取正文
  - [ ] 为什么需要分割（Chunking）：
    - [ ] 上下文窗口有限，不能把整本书塞进 Prompt
    - [ ] 小块检索更精准——不会把无关内容也带进来
  - [ ] 四种分割策略：
    - [ ] **字符分割**：按固定字符数切，最简单的基线
    - [ ] **递归字符分割**：按 `\n\n` → `\n` → `。` → `，` 优先级逐级回退，尽量保留自然边界
    - [ ] **语义分割**：按段落/句子边界切，保留完整语义单元
    - [ ] **滑动窗口（overlap）**：相邻 chunk 共享一部分内容，防止关键信息正好落在边界上被切断
  - [ ] `chunk_size` 怎么选：
    - [ ] 太小（<200）→ 语义不完整
    - [ ] 太大（>2000）→ 检索精度下降，噪声多
    - [ ] 经验值：500-1000，根据文档密度调整
  - [ ] `chunk_overlap` 怎么选：
    - [ ] 通常取 chunk_size 的 10%-20%
    - [ ] 代码/技术文档 overlap 可以大一些（信息密度高）
  - [ ] 元数据保留：`{source: "xxx.pdf", page: 3, title: "第一章"}`

- [ ] 写了什么代码
  ```
  week04/day02/loader_splitter.py — 加载 PDF/MD/TXT + 四种分割策略对比
  week04/day02/test_docs/
    ├── sample.pdf                — 测试用 PDF（找一篇短论文或技术文档）
    ├── sample.md                 — 测试用 Markdown
    └── sample.txt                — 测试用纯文本
  ```

  代码里打印每种分割策略的结果：
  - chunk 数量
  - 每个 chunk 的前 50 个字符预览
  - 有没有 chunk 被切断了句子？
